# Glossary

Non-normative. Each term is defined in a single table row; no explanatory prose is added.

| Term | Definition |
| --- | --- |
| dPLaaX / dplaax | Protocol name (display form) / wire namespace (the prefix of `dplaax.*.v1`, `did:dplaax`, etc.) |
| data pipeline (broad sense) | Any flow in which data is handed across boundaries; not limited to purpose-built pipeline products |
| process boundary | A boundary where a data handoff occurs; the unit at which records are issued |
| wire profile | The bundle of choices an implementation declares (algorithms, representation forms, etc.). What dPLaaX standardizes is structure and adjudication, not the choices themselves |
| conformance class | The unit that scopes rule applicability, expressed by a rule entry's `class` field |
| chain origin | A credential that carries no previousCredential and starts a new chain |
| process type | The classification of a pipeline process's behavior (Chained Process / Source Process / Sink Process / Custom Process), determined by signing behavior on the wire: a Source Process starts a chain (chain origin), a Chained Process continues it (carries previousCredential), a Sink Process ends it (verifies; by default emits nothing in-network — a wire profile can opt in to delivery receipts, see process.sink.receipt). Every pipeline participant holds a Process DID — the catalog classifies processes. (Formerly "component type": FilterConvert / Origin Source / External Sink / Custom — note kept through 0.x, removed at GA) |
| audit-reachable | An optional conformance class providing audit reachability across aggregation boundaries (see rules/commitment.yaml) |
| trust layering (L1/L2/L3) | Reserved for authentication (AUTH) contexts — the per-request bearer/PDP and wire-authentication surfaces. Provenance evaluation is no longer expressed as L1/L2/L3; it uses named scopes (rules/claims.yaml: claims.scope.named). The former provenance layering gloss (per-credential axes / audit reachability / semantic audit) is superseded by the scope catalog; the three confidence axes (rules/confidence.yaml) remain an internal composition input |
| named scope | A versioned identifier for one evaluation the protocol makes about a credential or chain (rules/claims.yaml) — the external claim vocabulary that replaces provenance L1/L2/L3. Examples: CREDENTIAL_ATTESTATION, LINEAR_ATTESTATION@1, SOURCE_SET_BINDING, SIGNATURE_ONLY@1 |
| evidence vector | The list of named scopes a verifier reports, each with a coverage and (when evaluated) a truth-state (claims.coverage.three-value). A durable artifact; crossing a trust boundary it is committed by a signature or checkpoint (claims.vector.durable-commit) |
| coverage / truth-state | The two axes of a scope result. Coverage ∈ {EVALUATED, NOT_EVALUATED, UNSUPPORTED} records whether the scope was assessed; truth-state ∈ {FAILED, INDETERMINATE, VERIFIED} records the outcome and is present only when coverage is EVALUATED (claims.coverage.three-value) |
| decision profile | A versioned policy that maps an evidence vector to a decision — ACCEPT / QUARANTINE / DENY — over the scopes it requires (claims.policy.profile-derived). Archetypes: evidence-archive, provenance-release, external-effect |
| WireVariantID | The digest of a versioned canonical wire projection of a proof-bearing credential — the immutable identity of one proof variant under a body (rules/identity.yaml: identity.wire-variant-id). Frozen form (P0-4): `wire:v1:jcs-rfc8785:sha256:<hex>` (identity.wire-variant-id) |
| EvidenceViewID | The digest of an EvaluationViewManifest (head + ordered variant spine + claim contract + input-snapshot digests) — the exact key a terminal verdict is bound to and reused by (rules/evidence-view.yaml: evidence.manifest.identity, evidence.cache.exact-view) |
| attribution computation | The audit-side actor that maps a verified chain to responsibility: which Owner DID answers for which segment, and for everything preceding the chain origin (see rules/audit.yaml). A deterministic function of chain topology; it reads no payload content |
| transfer relationship | A conveyance relationship between two process boundaries across which credentials are handed on (the direct heir of the earlier "転送関係" framing). The catalog fixes the evidence records this relationship leaves (see rules/transfer.yaml); the conveyance mechanisms themselves — admission control, request shapes, wire authentication, delivery-mode semantics — are wire-profile / service-API concerns, not protocol rules |
| ingress store | The durable, byte-preserving, audit-enumerable retention a consuming process keeps of the credentials it received (defined by transfer.ingress.retention). It is the counterparty record that source-commitment omission detection reconciles against (see commitment.class.definition, commitment.store.persistence). Provenance credentials only — not payload bytes |
| quarantine entry | The atomically persisted record of one received delivery awaiting release: exact wire variant, payload bytes and digest, delivery metadata, sink profile (effect.quarantine.atomic-entry). The custody chain between evaluation and external effect |
| ReleaseAuthorization | The immutable, integrity-protected artifact that is the sole capability for an irreversible external effect (effect.authorization.artifact): it commits to the exact quarantine bytes, the exact EvidenceViewID, the required scope set, the policy snapshot, and a validity bound. Schema: release-authorization.json |
| effect status | The closed quarantine/release state machine of a sink entry (effect.state.closed-machine). The only success state is EFFECT_CONFIRMED (target confirmation observed); EFFECT_UNKNOWN records an ambiguous external write without guessing it into failure |
| ObservationRecord / DecisionRecord | The archive split (effect.archive.observation-record / .decision-record): an ObservationRecord says "these exact bytes were observed" (coverage NOT_EVALUATED, never acceptance); a DecisionRecord joins it to the EvidenceViewID under which an actionable decision was made |
| delivery identity | The minimum discriminator set for one external delivery — sink contract, sink instance, target namespace, entry/occurrence, body/variant (effect.delivery.identity). An idempotency key coarser than this collapses distinct legitimate deliveries |
| release subject | The exact output artifact digest a release is about (release.subject.exact-digest). Tags, branches, versions, and source commits are locators/metadata, never the identity |
| immutable artifact | The claim that the released bytes cannot be silently re-pointed: subject digest + digest-pinned inputs + build-once (IMMUTABLE_ARTIFACT@1). Says nothing about whether anyone else can rebuild them |
| reproducible build | The strictly stronger claim (REPRODUCIBLE_BUILD@1) that an independent clean build derives the same digest; needs the full build-input closure enumerated and a second-builder digest match (release.claim.reproducible-separate) |
| clean scan | A bounded verdict: no known finding for the stated scanner, database snapshot, policy, and subject (release.scan.bounded-clean). Not an absence-of-vulnerabilities claim, and never derived from TOOL_ERROR / DB_STALE / UNSUPPORTED |
| component absent | The only advisory assessment that exits the waiver path: the component does not appear in the final artifact's SBOM (release.advisory.component-absent). Every component-present judgement stays a finding under waiver discipline |
| unreachable / potentially reachable | Reachability classifications of a present component (advisory-assessment.json). Unreachable is an assessment bound to exact digests, entrypoints, platform, and scanner assumptions — it erases nothing and needs a dated waiver; without positive evidence the default is potentially reachable |
| trusted build provenance | Provenance whose verifier pinned repository, workflow path, source commit, builder identity, subject digest, and predicate type (release.provenance.trusted-builder). The existence of a signed attestation alone is self-attestation, not trust |
